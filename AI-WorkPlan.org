* Stage 1: containerProc spcs framework

Goal: Build the =bisos.dockerProc= package as a full bisos-pip PyCS seed package
that manages Docker/Podman container image lifecycle via Spread Planted Command
Services. The leaf directory path in =bro_dockerfiles= is the configuration ---
the seed parses =plantOfThisSeed= to derive all operating parameters. Docker
leaves plant =dockerProc.spcs=; rootless-sysd leaves plant =podmanProc.spcs=.
Both delegate to the same =containerProc-seed.cs=.

** Naming conventions

| Artifact                  | Name                        | Rationale                              |
|---------------------------+-----------------------------+----------------------------------------|
| pip package               | =bisos.dockerProc=          | Short, matches image repo context      |
| docker planted file       | =dockerProc.spcs=           | Engine-explicit; used in docker leaves |
| podman planted file       | =podmanProc.spcs=           | Engine-explicit; used in podman leaves |
| seed entry point          | =containerProc-seed.cs=     | Engine-agnostic abstraction            |
| seedInfo module           | =containerProc_seedInfo.py= | =container_= prefix = engine-agnostic  |
| csu module                | =containerProc_csu.py=      | Same                                   |
| seed registration module  | =containerProc_seed.py=     | Same                                   |

** Path-to-parameter mapping

The leaf path =debian/<release>/<profile>/vnc/xfce/<imageName>/= encodes:

| Path segment  | Parameter derived                                                       |
|---------------+-------------------------------------------------------------------------|
| =debian=      | distro                                                                  |
| =<release>=   | 12 or 13 → base OS, base image tag                                     |
| =<profile>=   | =confined= / =privileged= / =rootless-sysd= → engine, init, privilege  |
| =vnc/xfce=    | desktop type → VNC/noVNC ports, xstartup variant                       |
| =<imageName>= | image name → DockerHub name, container name                             |

From these the seed derives: engine (docker vs podman), base image name, host
port assignments, =--privileged= flag, =--isolation=chroot= for rootless,
=--systemd=always= for podman, cgroup variant support.

** Planted files per profile

| Profile         | Planted file      | Engine |
|-----------------+-------------------+--------|
| =confined=      | =dockerProc.spcs= | docker |
| =privileged=    | =dockerProc.spcs= | docker |
| =rootless-sysd= | =podmanProc.spcs= | podman |

** spcs background

A =.spcs= (Spread Planted CS) receives parameters from both the file content
and the directory path in which it resides. The same file content is spread
identically across many directories; each instance is contextualised entirely
by its location.

Reference: =bisos-pip/_skills/spread-seeded-cs-commands/SKILL.md=
Precedent: =pypiProc.sh= (bash) planted in 50+ =bisos-pip/<pkg>/py3/= dirs.

* Stage 4: Implement the Platform Registrar

Goal: Make the design in the =containerProcArchitecture= figure real.
Introduce a per-user, per-image, per-instance registrar on the Container
Platform that assigns host-side ports, so multiple users on one VM ---
and multiple instances of one image per user --- no longer collide on
the fixed 2222/2223/... port table.

The registrar is a =bisos.regfps.RegFPs= subclass following the precedent
of =bisos.siteRegistrars.containerRegfps.Container_RegFPs=. Storage
lives at =/bisos/platform/registrar/dockerProc/<user>/<imageName>/instance<N>/=;
each instance directory is a =RegFPs= unit whose file-parameters
carry the assigned =sshPort= / =vncPort= / =novncPort= (plus
=engine=, =profile=, =plantPath=, =createdAt= for diagnostics).

Two consumers must be wired --- =.spcs= (on the platform) and Remote User
(over ssh). The design figure already shows both.

** Naming conventions

| Artifact                    | Name                                | Rationale                                    |
|-----------------------------+-------------------------------------+----------------------------------------------|
| RegFPs subclass             | =DockerProc_RegFPs=                 | Matches =Container_RegFPs= naming in siteRegistrars |
| Registrar module            | =containerProc_regfps.py=           | Alongside containerProc_seedInfo, containerProc_csu |
| Standalone registrar CS     | =dockerProcRegistrar.cs=            | Direct admin/inspection of the registrar     |
| Remote-user helper CS       | =dockerProcRemoteConfig.cs=         | Generates .ssh/config on remote user's host  |
| RegFPs base path            | =/bisos/platform/registrar/dockerProc/= | Matches figure; per-user subdirs beneath |

** Storage layout (registrar file tree)

#+begin_src
/bisos/platform/registrar/dockerProc/
  <user>/                          # posix login name
    <imageName>/                   # e.g. bisos_deb13-sysd
      instance0/                   # RegFPs unit dir
        fps/
          sshPort/value            # assigned host-side ssh port
          vncPort/value
          novncPort/value
          engine/value             # docker | podman
          profile/value            # confined | privileged | rootless-sysd
          plantPath/value          # source leaf path (for round-trip)
          createdAt/value          # ISO timestamp
      instance1/
      ...
#+end_src

Port allocation pool: e.g. =sshPort= in =20000--29999=, =vncPort= in
=30000--39999=, =novncPort= in =40000--49999=, allocated by
=unitsNextNu()= against the union of already-assigned ports in that pool
(scanning all users, since ports are host-global).

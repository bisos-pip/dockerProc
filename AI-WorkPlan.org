* Stage 1: containerProc spcs framework

Goal: Build the =bisos.dockerProc= package as a full bisos-pip PyCS seed package
that manages Docker/Podman container image lifecycle via Spread Planted Command
Services. The leaf directory path in =bro_dockerfiles= is the configuration ---
the seed parses =plantOfThisSeed= to derive all operating parameters. Docker
leaves plant =dockerProc.spcs=; rootless-sysd leaves plant =podmanProc.spcs=.
Both delegate to the same =containerProc-seed.cs=.

** Naming conventions

| Artifact                  | Name                        | Rationale                              |
|---------------------------+-----------------------------+----------------------------------------|
| pip package               | =bisos.dockerProc=          | Short, matches image repo context      |
| docker planted file       | =dockerProc.spcs=           | Engine-explicit; used in docker leaves |
| podman planted file       | =podmanProc.spcs=           | Engine-explicit; used in podman leaves |
| seed entry point          | =containerProc-seed.cs=     | Engine-agnostic abstraction            |
| seedInfo module           | =containerProc_seedInfo.py= | =container_= prefix = engine-agnostic  |
| csu module                | =containerProc_csu.py=      | Same                                   |
| seed registration module  | =containerProc_seed.py=     | Same                                   |

** Path-to-parameter mapping

The leaf path =debian/<release>/<profile>/vnc/xfce/<imageName>/= encodes:

| Path segment  | Parameter derived                                                       |
|---------------+-------------------------------------------------------------------------|
| =debian=      | distro                                                                  |
| =<release>=   | 12 or 13 → base OS, base image tag                                     |
| =<profile>=   | =confined= / =privileged= / =rootless-sysd= → engine, init, privilege  |
| =vnc/xfce=    | desktop type → VNC/noVNC ports, xstartup variant                       |
| =<imageName>= | image name → DockerHub name, container name                             |

From these the seed derives: engine (docker vs podman), base image name, host
port assignments, =--privileged= flag, =--isolation=chroot= for rootless,
=--systemd=always= for podman, cgroup variant support.

** Planted files per profile

| Profile         | Planted file      | Engine |
|-----------------+-------------------+--------|
| =confined=      | =dockerProc.spcs= | docker |
| =privileged=    | =dockerProc.spcs= | docker |
| =rootless-sysd= | =podmanProc.spcs= | podman |

** spcs background

A =.spcs= (Spread Planted CS) receives parameters from both the file content
and the directory path in which it resides. The same file content is spread
identically across many directories; each instance is contextualised entirely
by its location.

Reference: =bisos-pip/_skills/spread-seeded-cs-commands/SKILL.md=
Precedent: =pypiProc.sh= (bash) planted in 50+ =bisos-pip/<pkg>/py3/= dirs.

** TODO [#B] Graph Layerings :aiAndMe:
SCHEDULED: <2026-08-10 Sun>
Three execution platforms, shown as three distinct colors/swim-lanes:
1=remoteUser, 2=containerPlatform, 3=containerInstances.

- Remote User  (Bottom Layer)
  May be a machine  that only has port 22 open (corporate env where other
  than port 22 is blocked).
  So it needs an ssh tunnel to the host.
  bisos.dockerProc needs  to give the Remote user the .ssh/config entries for tunnel and ssh to local host.
  Remote User is a *consumer of the registrar*: it reads assigned port numbers to
  generate its =.ssh/config= tunnel entries (=LocalForward= lines).
- Conatiners Host (on top of Remote User)
  Runs everything. Interacts with remote user.
  Hosts the Platform Registrar (design-only in this phase; not implemented).
- bisos.dockerProc Platform Registrar (on top of container host)
  In /bisos/platform/registrar/dockerProc/<user>/<imageName>/instance0(through N/)
  Maintains port numbers for what the image exposes.
  Use case that motivates it: one powerful VM, 10 users, each user with one or more
  container instances --- fixed ports (2222/2223/...) collide, so the registrar
  assigns and tracks host-side ports per-instance.
  *Two consumers*:
    - =.spcs= (on the platform) --- reads assigned ports when doing =run= /
      =composeUp= / =verify=.
    - Remote User --- reads assigned ports to generate =.ssh/config= tunnel entries.
- images Path  -- The leafs where the dockerProc.spcs reside.
  Path gives the *image* identity; registrar gives the *instance* identity.
- Images and instances
  Shows the image and its naming  as one. and Instances and their namings as many.

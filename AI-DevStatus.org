** Path-to-parameter mapping

The leaf path =debian/<release>/<profile>/vnc/xfce/<leafName>/= encodes:

| Path segment | Parameter derived                                                       |
|--------------+-------------------------------------------------------------------------|
| =debian=     | distro (anchor segment)                                                 |
| =<release>=  | 12 or 13 → base OS, base image tag                                      |
| =<profile>=  | =confined= / =privileged= / =rootless-sysd= → engine, init, privilege   |
| =vnc/xfce=   | desktop type                                                            |
| =<leafName>= | image name (minus a =-<N>= suffix: secondary instance of the primary's) |

Container name and host ports come from the leaf's compose / Quadlet file.
=paramsFromPlantPath()= anchors on the ="debian"= segment and raises =ValueError= on an
unexpected path.

** CS commands

- =containerProc_imageBuild= / =imageDelete= --- build (copies =common/raw-bisos=; nothing in a
  secondary leaf) / remove the image.
- =containerProc_instanceUp= --- checks (engine, compose file, image built, host ports free), then
  create + start; =instanceDown= / =instanceRestart= / =instanceDelete=.
- =containerProc_instanceVncPassword= --- =set= / =clear= the optional VNC password (by =cp=).
- =containerProc_instancePs= / =instanceLogs= / =instanceExec= --- inspection.
- =containerProc_exec_installRawBisos= --- run =installRawBisos.sh= in the container.
- =containerProc_instanceVerify= / =instanceStatus= --- ports, noVNC, systemd via ssh / state and
  VNC auth mode.
- =containerProc_instanceCommit= / =imageSave= --- snapshot / save to the backups dir.
- =containerProc_fullClean= --- =instanceDelete= + =imageDelete=.
- =containerProc_imageIsStale= / =instanceIsStale= --- read-only staleness verdicts for walks.
- =containerProc_build= ... =containerProc_clean= --- deprecated aliases (delegate).
- =fto_*= (from =bisos.fileObj.ftoLeaf_csu=) --- lifecycle verbs and gate commands.

Lifecycle actions: =fto_prepare= = =imageBuild=; =fto_materialize= = =instanceUp=;
=fto_reMaterialize= = re-create a stale instance, VNC password kept; =fto_unMaterialize= =
=instanceDelete=; =fto_clean= = remove the image and copied =raw-bisos/= (refused while used);
=fto_verify= / =fto_status= = =instanceVerify= / =instanceStatus=.

* Key Design Decisions

- *Package name =bisos.dockerProc=, internal prefix =containerProc_=* — external name
  reflects dominant toolchain; internal modules signal engine-agnostic abstraction.

- *Two planted file names: =dockerProc.spcs= and =podmanProc.spcs=* — engine-explicit and
  visible to engineers at the leaf level; both delegate to the same =containerProc-seed.cs=.

- *=paramsFromPlantPath()= is a pure function* — no side effects; anchors on ="debian"=
  segment (not numeric index from root) for portability across machines.

- *Stale vagrant copies renamed to =*.vagrant-orig=* — preserved for reference but not
  imported; new containerProc_* modules replace them entirely.

- *=bisos.vagrantBaseBoxes= removed from requires* — was pulled in by the stale copies;
  the new package has no vagrant dependency. *Correction 2026-10-26:* still required ---
  =py3/bin/dockerProc.cs= / =exmpl-dockerProc.cs= (shipped scripts) import =vagBoxes_csu=; see the
  Stage 5 TODO "Retire the vagrant-derived legacy scripts". =setup.py='s =requires= now comes from
  =requirements.txt= (=pypiProc.sh -i genPipreqs=).

- *=containerProc_verify= is exec-free for rootless* — =podman exec= is unreliable on
  old Podman (4.3.1) for systemd containers; SSH-based checks match the existing
  =verify.sh= behaviour.

- *cgroup v2 hosts only (2026-10-26, user decision)* — cgroup v1 is obsolete for
  bisos.dockerProc. =_refuseIfUnsupportedHost()= (in =_run()= and at the top of the instance,
  verify, status and fullClean commands) refuses a v1/hybrid host as well as running inside a
  container. The =cgroupVer= parameter is gone; =cgroupVariants= is =[V2]= for every profile.
  On a v1 host, bro_dockerfiles' standalone =imageBuild.sh= / =containerManage.sh= still work
  (privileged leaves via =docker-compose.cgv1.yml=, which only the standalone way uses).

- *=instanceUp= checks like =containerManage.sh create= (2026-10-26)* — engine usable, (docker)
  =docker-compose.yml= present, image built (compose runs =--no-build=), host ports free; reports
  every problem and changes nothing. Already running → no-op; stopped → started. =instanceDown=
  / =Restart= fail if the instance does not exist; =instanceDelete= is then a no-op. Podman
  =run= now also passes =--stop-signal SIGRTMIN+3= and =-v <leaf>:/shuttle/this= (parity with
  =containerManage.sh=). Ports checked are =paramsFromPlantPath()='s, which since Stage 9 reads
  them from the leaf's compose / Quadlet file, as the standalone way does --- sysd-2 included.

- *Optional VNC password; no password is the default (2026-10-26, user decision)* --- a state, not
  an option: no (or an empty) =/home/bystar/.config/bisosVncPasswd= in the container means
  =-SecurityTypes None=. The image's =/usr/local/bin/vncStart.sh= (bro_dockerfiles, confined
  image, inherited) decides at each VNC start. Set/clear with =containerProc_instanceVncPassword=
  / =containerManage.sh vncPassword=, by =cp= (not =exec=). Classic VNC auth: 8 characters, no
  encryption. Requires rebuilt images; untested on a daemon (Stage 8, 8.4).

- *Lifecycle verbs and gate from =bisos.fileObj= (Stage 10, 2026-10-26)* --- the =fto_*= verbs,
  gate and status log are =bisos.fileObj='s (=ftoLeaf_csu= on this seed's =csuList=); this package
  registers seven actions (=ftoLeaf_seedInfo.setup=). =containerProc-seed.cs='s =csuListImportPlus=
  dblock was regenerated by the user (2026-10-26). The Stage 9 entry below describes
  the first, in-package version; its gate commands and gated =containerProc_*= commands are gone.

- *Gated walks; =fto_= lifecycle verbs (Stage 9, 2026-10-26)* --- a CBM-style gate
  (=<leaf>/dockerProc.control=, =enabled= | =available= | =disabled=, missing = available) and
  status log (=dockerProc.status=) in each leaf, git-ignored in bro_dockerfiles (one user per VM,
  each with their own clone). Leaf verbs =fto_prepare= (= =imageBuild=, not gated),
  =fto_materialize=, =fto_reMaterialize= (stale only; keeps the VNC password), =fto_unMaterialize=,
  =fto_clean=; read-only =containerProc_imageIsStale= / =instanceIsStale=. deb13's branch file walks
  confined first. Secondary leaves (=<primary>-<N>=) now handled: the primary's image, their own
  container name and ports from the compose / Quadlet file (=_PORT_TABLE= is a fallback).
  Untested on a daemon (Stage 9, 9.7).

- *Complete RawBisos-Reconstruction in one walk --- TODO (Stage 11, 2026-10-27, user decision)* ---
  today the bootstrap (=containerProc_exec_installRawBisos=) is a walk of its own and

  =fto_materialize= / =fto_reMaterialize= run them. bro_dockerfiles' README documents today's steps
  ("RawBisos-Reconstruction: BISOS's CI/CD") and its new "Walking the Tree: Lifecycle Verbs".

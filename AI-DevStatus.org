** Path-to-parameter mapping

The leaf path =debian/<release>/<profile>/vnc/xfce/<imageName>/= encodes:

| Path segment  | Parameter derived                                                       |
|---------------+-------------------------------------------------------------------------|
| =debian=      | distro (anchor segment)                                                 |
| =<release>=   | 12 or 13 → base OS, base image tag                                     |
| =<profile>=   | =confined= / =privileged= / =rootless-sysd= → engine, init, privilege  |
| =vnc/xfce=    | desktop type → VNC/noVNC ports, xstartup variant                       |
| =<imageName>= | image name → DockerHub name, container name                             |

=paramsFromPlantPath()= anchors on the ="debian"= segment in =plantOfThisSeed=.
Raises =ValueError= loudly on unexpected path structure.

** UNTESTED --- verification required on a VM

The 10-item verification checklist is in =AI-WorkPlan.org= under the
"Addition of container saving/backup..." TODO's AI Results section.
Key risk points:

1. =/bisos/var/dockerProc/backups/<user>/<imageName>/= writability for
   rootless-podman users --- if this fails, switch to a user-local path
   for podman (mode "c" of the S2 design question).
2. The commit source container name is assumed to equal =p.imageName=
   (BISOS "one instance per leaf" convention). If a leaf's compose file
   or run command uses a different container name, =commit= will fail.
3. First-invocation symlink creation is =try/except OSError= (warns on
   failure); should be exercised with both docker (multi-user, likely
   root-owned =/bisos/var/=) and podman (user-owned) contexts.

* Key Design Decisions

- *Package name =bisos.dockerProc=, internal prefix =containerProc_=* — external name
  reflects dominant toolchain; internal modules signal engine-agnostic abstraction.

- *Two planted file names: =dockerProc.spcs= and =podmanProc.spcs=* — engine-explicit and
  visible to engineers at the leaf level; both delegate to the same =containerProc-seed.cs=.

- *=paramsFromPlantPath()= is a pure function* — no side effects; anchors on ="debian"=
  segment (not numeric index from root) for portability across machines.

- *Stale vagrant copies renamed to =*.vagrant-orig=* — preserved for reference but not
  imported; new containerProc_* modules replace them entirely.

- *=bisos.vagrantBaseBoxes= removed from requires* — was pulled in by the stale copies;
  the new package has no vagrant dependency.

- *=containerProc_verify= is exec-free for rootless* — =podman exec= is unreliable on
  old Podman (4.3.1) for systemd containers; SSH-based checks match the existing
  =verify.sh= behaviour.

- *=degraded= is WARN not FAIL in verify* — polkit is masked in all sysd images
  (unavoidable in containers); three services active is the real gate.
